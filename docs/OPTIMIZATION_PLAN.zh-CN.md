# 星幕 AI 影像工作台：完整项目优化与修复方案

版本：1.0；基线日期：2026-09-05；面向执行者：5.6 luna；执行方式：单个智能体按任务依赖持续实施。

配套文件：[审计证据](./AUDIT_BASELINE_2026-09-05.md)、[持续执行提示词](./LUNA_CONTINUOUS_PROMPTS.zh-CN.md)、[进度账本](./OPTIMIZATION_PROGRESS.md)。

## 1. 总体判断与完成目标

项目已有小说解析、剧本/角色/分镜、模型路由、手动回收、画布、时间线和本地存储等主体。当前最需要补齐的是：数据可靠性、真实音视频编辑与成片、后台任务恢复、统一数据契约、可重复验收。继续增加界面入口或模型名称不能解决这些问题。

当前构建通过，16项现有无真实服务审计通过；但已确认渲染器使用同一默认图片合成各段，声音被去除；前端导出仅JSON。还存在画布未导入函数、浏览器配额阻断保存、旧任务跨项目写回路径和评分误判。详细位置见审计基线。

默认产品目标为 **Windows 本地优先、单用户使用、支持真实素材的完整创作工作台**。保留现有 React + Vite + Node + FFmpeg；先完成可靠闭环，再扩展多人联网版本。不要整仓改写框架。

必须分开记录以下交付等级，避免混淆：

| 等级 | 可交付标准 |
| --- | --- |
| `local_v1` | 无云端密钥也能导入自己的剧本与媒体，完成编辑、真实预览/代理预览、MP4导出、项目包迁移与重启恢复；基础安全和故障测试通过 |
| `api_verified_v1` | 在 local_v1 上，至少一条文本、图片、语音、视频实际配置路线完成授权后的真实验证；记录模型、时间、任务ID、资产和费用边界 |
| `hosted_v2` | 在前述基础上增加登录、项目权限、限额、共享资源隔离、HTTPS和部署恢复；仅用户选择联网版后实施T24 |

local_v1 可以交付给单机用户。未验证真实API时必须显式保留 `api_verified_v1=pending`，不能把适配器或模拟返回当成验证完成。

首版业务范围：TXT/Markdown小说、结构化剧本和既有星幕JSON导入；角色/场景/道具/逐句声音；外部素材回收与可选API生成；单集独立分镜和时间线；画面、旁白/对白、音乐、字幕轨；裁剪、拆分、移动、变速、静音/音量、基础转场；9:16和16:9输出；项目包与SRT导出。暂不把团队协作、收费系统、自动社交平台发布、专业调色或任意复杂特效设为首版前置条件。

## 2. 实施原则与优先级

- **P0：** 会丢数据、跨项目串写、核心操作直接报错、生成结果不真实，以及真实编辑/导出闭环的阻断项。先处理。
- **P1：** 使闭环稳定、可恢复、可迁移、可安装的必要工作。
- **P2：** 大规模性能、体验增强和可选联网扩展。出现实测瓶颈时提升优先级。
- 修复前给现状留可恢复快照；保护 `.env`、供应商配置、音色库、`server/data`、用户媒体和素材交付目录。任何清理先列具体路径并确认不会误删用户产物。
- 新增或修复一个能力，需要同时说明数据如何存、UI如何用、后端如何执行、失败如何显示、刷新如何恢复、怎样验证。
- 模型产物、手动导入和确定性演示必须保留来源。演示资源不得满足真实成片质量门禁。
- 先完成明确可支持的编辑操作。尚未实现的能力应显示“暂不支持”及原因，不得点击后只弹“已应用”。
- 先验证可还原的行为，再做结构重构。不要用删除断言、放宽门禁或长期吞异常换取测试通过。
- 默认不开子智能体；不自动购买资源、触发收费API、公开部署或向第三方发送消息。软件实现与隔离测试持续推进，不因暂缺密钥停止全部任务。

### 3.1 项目、素材和版本

定义版本化 `Project`：`schemaVersion / id / revision / title / settings / sourceDocumentId / episodes / characters / assets / shots / tracks / clips / generation / delivery / createdAt / updatedAt`。

- `settings` 至少包含画幅、输出宽高、fps、背景填充策略和音频采样率。首版验证24/25/30fps，其余帧率未实现时明确拒绝。
- `Episode / Scene / Dialogue / Shot` 均有稳定ID；跨实体用ID引用，不用数组下标、角色显示名或拆出来的clip名称当主键。
- `Asset` 包含 `id / projectId / kind / localRelativePath / mime / bytes / sha256 / durationUs / width / height / fps / sampleRate / channels / source / provenance / createdAt`。
- `source` 至少区分 `imported / generated / demo`；生成来源包含provider、model、jobId、promptVersion与输入摘要；不存密钥。
- 大媒体和小说原文独立落盘，不放入全量项目JSON或localStorage。项目只保留引用和摘要；原文文件保留哈希与章节索引。
- `revision` 防并发覆盖；`schemaVersion` 管数据升级。两者不能混用。

### 3.2 时间线契约：必须先统一，再修前后端

采用项目帧作为时间线单位：`startFrame / durationFrames` 是整数；源素材入点用 `sourceInUs` 微秒；`playbackRate > 0`。首版限制在声明支持的速度范围内。

```json
{
  "id": "clip-a",
  "trackId": "track-video-1",
  "kind": "video",
  "sourceAssetId": "asset-a",
  "shotId": "shot-01",
  "startFrame": 0,
  "durationFrames": 72,
  "sourceInUs": 2000000,
  "playbackRate": 1,
  "gainDb": 0,
  "muted": false,
  "transform": { "scale": 1, "x": 0, "y": 0, "rotation": 0 },
  "effects": []
}
```

定义：源时间 = `sourceInUs + round((播放帧-startFrame) / fps × playbackRate × 1,000,000)`。在相对第k帧拆分时，第二段 `sourceInUs` 增加 `round(k/fps × playbackRate × 1,000,000)`。输入框显示秒，统一转换函数负责帧对齐。

轨道类型为 `video / audio / caption`，有稳定ID、顺序、锁定/静音属性。字幕保存文本及样式；所有编辑命令经过同一个校验和undo/redo入口。旧 `track=0/1/2/3`、`start/duration` 在迁移层转换，禁止业务中反复猜测。

### 3.3 任务与执行结果

统一任务字段：`id / projectId / targetId / taskType / inputRevision / inputHash / idempotencyKey / provider / model / providerTaskId / state / attempt / progress / leaseUntil / cancelRequestedAt / resultAssetIds / error / createdAt / updatedAt`。

状态机：`queued → running → waiting_provider → downloading → validating → succeeded`；分支允许 `retry_wait / failed / cancel_requested / cancelled / awaiting_manual / awaiting_budget / needs_reconcile`。不能从终态被旧轮询降级回running。所有文本、图像、TTS、视频、渲染都使用该体系。

统一错误：`{code,message,retryable,requestId,details}`。前端展示可操作原因；后台日志带projectId/jobId/requestId并脱敏。

供应商登记必须分开 `displayName / provider / apiModel / adapter / supportedTasks / capabilities / accessMode / verifiedAt`。界面显示名不等于API模型ID；官方模型与限额在实施时查询官方资料，不按本文日期推断最新能力。

## 4. 明确任务卡

### T01 — 工程基线、开发连通和最低检查（P0）

涉及：`package.json`、`vite.config.js`、`.gitignore`、`scripts/*audit.mjs`，新增环境诊断与lint配置。

1. 在保护用户数据前提下建立代码快照/本地Git基线；有Git后先看现有变更，不能重置用户修改。备份/生成目录先加入忽略规则再提交代码。
2. 固定 `packageManager` 和实际验证过的Node范围，保留唯一锁文件；不得顺手全量升级依赖。
3. 增加 `/api` 到本机编排服务的开发代理，以及统一开发启动入口；开发服务默认绑定回环地址。现有相对API路径保留。
4. 加入ESLint的未定义变量、React Hooks、未处理Promise检查；核心共享逻辑先用JSDoc/checkJs或逐模块TypeScript，不强制全仓重写。
5. 新增统一离线 `test`/`check` 脚本；把 `test:voices` 改为临时数据目录注入，不能依赖真实音色库内容。

验收：干净目录按README能安装；开发页面能访问真实本地 `/api/health`；测试不碰用户数据、不请求外网；未导入函数可在检查中被发现。旧源码正则测试若与格式化冲突，先转为行为/结构测试，再删除过时正则。

### T02 — 直接报错、异步串写与虚假成功（P0）

涉及：`src/FreeformCanvas.jsx:97`、`src/main.jsx:516,517,564`、相关请求工具。

1. 从 `shared/creativeContext.mjs` 正确导入 `scenePromptContext`；保持画布编译上下文一致。错误处理中的剪贴板失败独立捕获，不能盖掉原错误。
2. 生成操作捕获 `projectId + targetId + inputRevision`；每个await之后及写回时重新验证。切换项目/卸载使用AbortController或忽略过期结果。
3. 画布结果追加使用最新节点/边状态，避免请求期间新增节点被旧闭包覆盖；允许多个任务时用按jobId的状态，不用一个generatingId表示全部任务。
4. 上一/下一剪辑点实现真实定位；未实现特效暂时明确禁用，完成T10后按能力开启。

验收：画布图片生成使用本地受控返回可产生节点；剪贴板拒绝时仍显示生成原错误；A项目等待中切到B，A结果仅保存到A；生成中移动/添加节点不丢失；跳剪辑点真正改变播放位置。

### T03 — 保存可靠性、版本冲突和配置并发（P0）

涉及：`src/main.jsx:567`、`src/workflow.js:208`、`server/store.mjs:16`、`server/config.mjs:24`、项目PUT。

1. 将保存副作用移出状态updater；建立每项目SaveCoordinator，300–800ms可配置去抖、单次在途请求、dirty标识、只合并尚未提交的最新状态。
2. 浏览器缓存失败独立处理，继续服务端保存；大数据改为IndexedDB草稿，localStorage仅保存项目ID/主题等小字段。
3. 服务端读当前revision并比较expectedRevision，检查与写入必须在同一锁/事务内；冲突返回409和当前revision，UI提供保留本地副本、重新加载/显式合并。不得静默覆盖。
4. 保存成功返回revision；仅对应请求仍是当前最新修改时显示“已保存”。旧项目响应不能修改新项目的保存提示。
5. 当前JSON原子写继续保留；配置与音色库的read-modify-write使用同一序列化机制，临时名用UUID，失败清理只针对自身临时文件。
6. 离线状态、重试和未保存退出提醒明确；恢复服务后自动补交草稿，不靠页面卸载时一次请求兜底。

验收：localStorage抛配额错误时服务端仍收到保存；快速输入100次重开后内容一致；故意延迟旧保存响应不回滚新值；两个标签页改同项目触发冲突处理；并发改两个provider字段不丢另一项。

### T04 — 真实质量门禁与手动模式（P0）

涉及：`server/pipeline.mjs`、`src/productionPlan.js`、手动回收入口、`shared/creativeContext.mjs`。

1. 将“完整度评分”与“允许执行/交付”分离。done由必须条件全部满足决定；score仅展示进度；输出结构化blockers与warnings。
2. 按项目工作模式制定门禁：手动导入媒体的编辑项目不强求3场、4镜、角色三视图；AI一致性生产项目使用选定的参考视角要求，前后端同源。
3. 同一镜头多个片段不能替代另一个缺素材镜头；按shotId/assetId检查，媒体存在、可探测、来源非demo才算实际就绪。
4. 引入依赖版本：首帧/声音/镜头/字幕/质检引用输入hash，输入变化时标记stale；旧通过记录不得继续放行新成片。
5. 技术质检与人工艺术审查分开；粘贴 `decision=pass` 只能记录人工意见，不能替代视频文件检查。

验收：当前90分却done的探针改为blocked；重复视频/空URL/demo均不能满足真实交付；单镜头无对白的手动项目可合规导出；字幕或主镜头修改后需要重新验证对应结果。

### T05 — 本地服务访问、密钥、路径与请求边界（P0；联网前强制）

涉及：`server/index.mjs`、`server/config.mjs`、`server/store.mjs`、远程provider/本地TTS配置。

1. 保留127.0.0.1监听；增加严格Host允许列表和精确Origin策略。设计本地会话bootstrap：仅可信同源页面可获得短期会话，写请求需会话/CSRF校验；开发代理使用同一机制。不能把token硬编码进构建或URL。
2. 本地自动化CLI用独立凭据或显式本地会话；错误Host、来源、缺授权的配置写入/生成/删除返回明确401/403。
3. 移除客户端任意 `frameFile` 路径输入；渲染仅接受projectId/revision/assetId/preset。路径做规范化+目录边界检查，拒绝越界及不允许的链接目标。
4. 远程媒体下载限制供应商允许的域/协议；校验解析后的IPv4/IPv6和每次重定向，不得访问回环、私网、链路本地或元数据地址；DNS结果和实际连接要一致。
5. 本地TTS属于明确配置的回环适配器例外，仅允许登记端口和路径，不复用成通用HTTP代理。自定义OpenAI地址变更时展示将接收凭据的主机，按明确配置校验。
6. 请求类型/体积/并发限额按端点定义，非法JSON为400，超限413，未支持类型415，业务Schema422，未配置409，限流429，内部故障500。所有错误均脱敏。
7. 配置密钥只保留服务端；禁止写入项目包/日志/前端状态。Windows确认文件ACL；若采用系统凭据存储需有迁移与恢复方案，不能只凭POSIX mode断言Windows安全。

验收：错误Host/Origin、无会话写入、编码越界路径、内网及重定向下载均拒绝；本地TTS仍可用；项目导出、前端构建和日志中不出现测试密钥。已有Origin检查应复用加强。URL与上传规则参考[OWASP SSRF防护](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)和[文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)。

### T06 — 时间线数据、编辑命令与兼容迁移（P0）

涉及：`src/main.jsx`编辑器、`src/timelineMath.js`、`src/editingPlan.js`、`src/workflow.js`、新增shared时间线契约。

1. 实现第3.2节契约和旧项目幂等迁移；保留mediaUrl兼容读，统一写assetId。拆分后sourceIn不得归零。
2. 抽出 `split / trim / move / rippleDelete / duplicate / setSpeed / setVolume / setTransform / addCaption` 命令；手动和AI提案共用。
3. 校验负值、NaN、越过源素材长度、锁轨、非法重叠。首版同一画面轨不允许无定义的重叠；显式转场与上层轨合成单独定义。
4. 定义片段空隙=透明或项目底色；删除/ripple是否影响其他轨采用明确选项。变速时同步修改源覆盖区间与时间线时长。
5. undo/redo保存完整命令影响范围，包含轨道、字幕状态、片段关联；每一拖拽手势合并为一个历史项。

验收：用带递增时间码的10秒测试片，入点2秒、长度6秒，在第3秒拆分，第二段从源5秒开始；两段拼接总长保持6秒。加入2倍速后计算一致；撤销重做恢复全部字段；迁移两次结果不变。

### T07 — 媒体导入、下载、探测和播放服务（P0/P1）

涉及：`server/index.mjs:42,168`、`server/store.mjs`、`src/workflow.js:237`。

1. 上传/下载流式写 `.part` 文件，限制字节数、时长和并发，完成后校验并原子提交；断开、取消、超限清理自身临时文件。
2. 不信任扩展名/Content-Type；检查文件签名并用ffprobe获得真实音视频参数，图片解码检查。只接受明确支持的类型。
3. 媒体入库时计算哈希、尺寸、时长、编码、音轨，生成缩略图/波形/可选代理文件，记录关联assetId。

5. 统一可访问组件：弹窗焦点/ESC、按钮名称、键盘路径、长文本溢出、加载/禁用态和颜色对比；桌面优先，窄屏用于查看/轻量编辑。
6. CSS提取颜色/间距/字号令牌与模块样式，合并重复覆盖，减少全局!important。恢复残留文件经备份与引用确认后移出src，禁止作为代码生成源。

验收：初次打开能理解如何新建/导入和完成成片；错误可定位到任务/镜头；1366×768、1920×1080、900px与390px宽无主要按钮被遮挡；键盘可完成导入/切页/关闭弹窗；浏览器无未处理异常。

### T20 — 构建、长列表与媒体性能（P1/P2）

涉及：`vite.config.js`、静态服务、项目列表、分镜/画布/时间线与媒体缩略图。

1. 正常应用构建使用外部hash资源与按页/重模块拆包；示例大图取消内联，转换合适格式并按需加载。需要单文件演示时保留独立build:demo，不能限制正式应用架构。
2. 缓存不可变静态资产；入口HTML使用更新策略。避免每次请求同步gzip大页面，预压缩或采用不会阻塞事件循环的策略。
3. 项目列表分页/摘要查询；分镜/资产多时虚拟化；时间线可视窗口绘制、拖拽中局部状态、pointerup提交历史；波形/缩略图后台生成。
4. 记录固定夹具、浏览器/设备、冷缓存条件与测量方法，再优化瓶颈，不用未经测量的“提升80%”。

验收目标：首屏必需JS+CSS压缩后≤1.5MB，示例媒体不在关键包；同机性能相对当前基线有可复测改善；1000片段夹具下编辑不反复全量序列化，常见拖动每帧工作目标≤16ms，选中/拖动反馈p95≤100ms。这些是工程目标，需实测记录，未达标写明瓶颈。分包与代理配置依据[Vite构建配置](https://vite.dev/config/build-options.html)与[开发服务器配置](https://vite.dev/config/server-options)。

验收：统一check失败能定位具体行为；所有已修P0有回归用例；测试在空目录可重复，不初始化实际音色库；接口错误日志不包含测试密钥；CI禁止默认运行live-e2e。

### T24 — 多用户/公网版本（P2，可选扩展）

只有用户明确选择联网版后启动。加入用户/工作区、项目成员角色、服务端对象级授权、用户凭据隔离、调用配额/审计、上传和队列公平调度、HTTPS与持久备份。单机SQLite若迁移多机服务，评估PostgreSQL、对象存储与独立worker；共享配置/素材目录必须重新设计。

## 6. 最终验收矩阵

| 场景 | 操作 | 必须观察到的结果 |
| --- | --- | --- |
| 新机器启动 | 干净路径安装、无云密钥、无TTS | 页面可用；手动路线完整；可选缺项明确 |
| 既有项目兼容 | 导入旧星幕JSON | 数据迁移成功、ID/人物/场景/素材可追溯，无静默丢字段 |
| 手动短片 | 导入3段本地视频、人声、BGM、SRT | 不需要AI角色参考也能编辑和导出 |
| 编辑准确性 | 源入点、拆分、变速、空隙、静音、音量、字幕 | 预览/代理预览与成片一致；时长误差≤1帧 |
| 画幅/帧率 | 16:9与9:16；24/25/30fps | 文件探测符合所选设置，UI预设不写死 |
| 数据保护 | 连续输入、离线、配额耗尽、多标签冲突 | 无静默丢失；旧响应不回滚；冲突可处理 |
| 跨项目异步 | A生成时切B，A随后结束 | B不被污染；A重开看到结果或候选版本 |
| 后台恢复 | 各任务关键点终止worker后重启 | 已受理任务不盲目重提；结果不丢；失败可追踪 |
| 版本失效 | 改角色参考/台词/首帧/字幕 | 只有依赖下游变stale；旧审核不自动放行 |
| 导出恢复 | 运行中刷新、取消、同项目再次导出 | 状态可靠、URL独立、旧成片仍可访问 |
| 包迁移 | 导出便携包，在空数据目录导入 | 素材齐全、可重渲染、没有密钥/本机路径依赖 |
| 输入防护 | 损坏/超大/路径越界文件和不可信URL | 明确拒绝，无正式半成品、无任意本地文件访问 |
| 可用性 | 窄屏、键盘、网络错误、空项目 | 操作可达；错误有原因及恢复入口 |
| 真实性 | 未配置模型/不可用视频/人工pass但无文件 | 不计真实成功，不伪造素材、费用或验收结果 |
| 真实API | 仅授权后执行限额短样例 | 记录真实任务/产物；未执行保持pending |

建议固定一组由本地FFmpeg自行生成的测试夹具：不同颜色和时间码的视频、已知起点的提示音、中文/英文两行SRT、无声片和损坏文件。全部与用户真实数据隔离，可跨机器重跑。

## 7. 变更与验证规则

每次工作闭环为：读当前账本→复查目标代码→重现/写必要回归→最小修复→相关测试→集成验证→更新账本→继续下一项。

普通改文案/样式不编写镜像式测试；保存、渲染、异步、权限等关键行为必须有有意义的回归。项目目前部分测试只认源码字符串，格式化前应识别并替换脆弱断言。

React异步副作用需要清理或忽略过期结果，状态updater保持纯函数；实施参考[React Effect说明](https://react.dev/learn/synchronizing-with-effects)。这条规则应通过“切项目后旧请求返回”等行为验证，而不是仅搜索useEffect字样。

不要自动运行当前live-e2e；它会调用真实供应商。新命令如 `test:api`、`test:render`、`test:e2e:offline`、`doctor` 是本方案要求创建的目标，目前不应假定已经存在。进度报告必须区别“计划新增”和“已经执行”。
