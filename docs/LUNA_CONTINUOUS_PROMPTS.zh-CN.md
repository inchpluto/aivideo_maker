# 交给 5.6 luna 的持续执行提示词

使用方式：在当前项目目录中开启或继续执行任务，复制“首次启动提示词”。之后只在需要接续时使用“继续提示词”。执行规范、任务顺序和验收已在同目录主方案中，不需要每轮粘贴整份方案。

本文件是用户可以交给执行模型的指令模板；本次编制方案没有启动自动化、定时器或实际代码优化任务。提示词通过进度账本衔接上下文，不保证绕过会话或额度限制。

## 首次启动提示词

```text
你现在负责把当前项目“星幕 AI 影像工作台”优化成完整、可靠、可安装交付的项目。请直接实施，不停留在分析、建议或重复写计划。由你单独执行，不开启子智能体，也不另建任务。

工作目录：G:\vibecoding\codex_project\aiviedo_make

先阅读当前目录及父级适用的AGENTS.md，然后按顺序阅读：
1. docs/OPTIMIZATION_PROGRESS.md
2. docs/OPTIMIZATION_PLAN.zh-CN.md
3. docs/AUDIT_BASELINE_2026-09-05.md

用户目标：保留项目已有创作能力，修复实际缺陷，完成导入剧本/本地素材、剧本与角色/场景/道具/声音、分镜、画布、真实时间线剪辑、带声音字幕的MP4导出、后台任务恢复、项目包与备份恢复、环境安装和可靠验收。真实API能力单独验证。默认做Windows本地单用户完整版本，暂不启动可选T24联网扩展。

以主方案T01–T23和阶段依赖作为任务清单。计划编写日的代码证据需要复核，不把旧行号或旧QA当当前事实。当前已有原子文件写入、严格生成模式、手动素材回收、provider适配和部分测试，应保留有效能力后增量修复。

先做T01基线和开发连通，再推进T02运行时与跨项目异步、T03保存/版本冲突、T04门禁、T05基础边界，随后T06–T11打通无密钥真实成片。再按计划实施T13、T14、T12和其余依赖。测试随修复补充，不拖到最后。

每次执行循环：
- 读进度账本和相关代码，选择依赖已满足、优先级最高的未完成子任务。
- 说明本轮修复的具体行为；先复现关键缺陷或加必要回归。
- 完成必要的前端、后端、共享契约和测试改动，保持范围可审查。大任务拆成Txx.1/Txx.2，不重写整个项目。
- 执行相关检查，再验证跨模块行为。不要只运行build或源码正则就声称通过。
- 写入修改路径、实际命令/退出码、行为证据、风险和回滚方式；更新docs/OPTIMIZATION_PROGRESS.md。
- 当前子任务满足验收后，继续下一项依赖已满足的任务，不为了普通可逆修复反复询问“是否继续”。

特别必须修复：
- FreeformCanvas图片生成的scenePromptContext未导入。
- 浏览器localStorage配额错误使服务端保存完全不执行；保存副作用位于React状态updater；全量保存缺revision防覆盖。
- A项目等待任务后切B，旧结果可能写入B；画布旧闭包可能覆盖新增节点。
- 分镜评分90但缺首尾帧仍done；评分不能代替必须条件。
- 拆分/裁剪缺源入点，预览不是完整节目播放，部分按钮仅显示成功通知。
- server/render.mjs使用默认图片合成所有片段并去掉音频；前端只导出JSON。必须生成与时间线一致的真实MP4。

约束：
1. 不开启子智能体。保留React/Vite/Node/FFmpeg，按职责逐步拆模块，不无依据换框架。
2. 开始修改前建立可恢复代码基线。没有Git时先设置敏感/生成数据忽略并建立本地代码版本或等效快照；不覆盖用户现有改动，不把.env、server/data、音色、素材、缓存或日志提交进去。
3. 保护现有项目、密钥、媒体和音色库。测试注入独立DATA_DIR/受控provider，禁止测试默认读取或初始化真实音色库。清理前解析绝对路径并验证目标边界。
4. 不打印密钥，不把凭据写入前端/项目包/日志。不默认执行付费API、购买、公开部署或向外发送消息。已获授权的可逆代码修复持续做；确需新的费用或不可逆外部动作时，先完成全部可独立工作，再简洁说明所缺授权。
5. 未实现功能明确禁用/标注，不能只toast成功；demo不能通过真实交付门禁；模型/价格/配额不得编造。实施动态provider接口时核对官方资料，保留验证时间和证据。
6. 保持旧项目可读；schemaVersion与revision分开；迁移有备份、dry-run、幂等及回滚。重构不能让用户失去已有资产。
7. 不删除重要断言、不放宽质量门禁、不吞异常换取通过。旧正则测试妨碍合理重构时，先增加等价行为/结构验证再替换。
8. 本地素材导入、手动回收和离线真实渲染必须在没有云端密钥时可验收。缺密钥/GPU不阻断无依赖任务，把受阻能力独立记账。

持续执行与交接：
- 保持一个明确的currentTask/nextTask。不得仅因完成一条小修改就把整个项目标记完成。
- 遇到可修问题自行排查修复；遇到外部阻塞记录阻塞任务、原因、已尝试方法、需要什么输入，并继续其他可执行任务。
- 上下文或会话需要结束前，更新进度账本：最后可用状态、未提交改动、当前失败、下一条具体动作和命令，保证下一轮不从头审计。
- 不承诺后台无限执行；只有实际运行和测试过的内容可以写成完成。

最终完成必须满足主方案验收矩阵，并提供当前RELEASE_ACCEPTANCE报告。分别报告local_v1、api_verified_v1；没跑真实API就保持后者pending。可选hosted_v2未选择时标not_requested。

现在开始读取文件并实施第一项尚未完成的任务。当前阶段结束后继续下一项，直到T01–T23的可执行范围完成或只剩必须依赖用户/外部条件的阻塞。
```

## 继续提示词

```text
继续当前星幕项目优化。由你单独执行，不开子智能体，不另建任务，不重新从零规划。

先读docs/OPTIMIZATION_PROGRESS.md，检查工作区实际变更，再读当前任务在docs/OPTIMIZATION_PLAN.zh-CN.md中的要求。以最新用户指令和代码事实纠正旧记录。

从账本的currentTask/nextAction恢复：若前一轮有未完成修复或失败测试，先闭环；否则按依赖选择下一个最高优先级任务。完成必要代码、行为测试、文档后立即更新账本并继续下一项。不要只汇报建议或再次询问普通修复是否继续。

沿用首次启动提示词的全部约束：保护用户数据与密钥、测试隔离、不伪造成功、保持旧项目兼容、不触发未授权付费/发布、可独立工作持续推进。被外部条件阻塞的任务单独记录，不把整个项目提前标完成。

本轮结束前必须留下：实际完成项、修改路径、已跑命令与结果、当前失败/风险、下一条具体执行动作。若上下文不足，优先把精确交接写入账本，下一轮可直接继续。
```

## 最终验收提示词

```text
对当前星幕项目执行最终交付验收并修复发现的问题。单独执行，不开子智能体。

读取docs/OPTIMIZATION_PLAN.zh-CN.md第6节和docs/OPTIMIZATION_PROGRESS.md，不把旧QA或完成勾选当证据。逐项核实当前实现，并在独立测试数据目录执行：干净安装、旧项目迁移、手动媒体闭环、帧准确拆分/裁剪/变速、音频字幕、9:16/16:9导出、保存冲突、跨项目异步、worker重启/取消、素材版本失效、便携包导入、备份恢复和请求/文件边界测试。

真实成片要提供ffprobe摘要及必要抽帧/音频时间证据；浏览器测试要验证操作结果，不能仅断言提示文案。发现P0/P1就按最小范围修复、回归并更新账本。

真实API只在已有明确费用授权/凭据且限额生效时运行；否则保留api_verified_v1待验证，说明缺什么，不跑demo冒充。输出docs/RELEASE_ACCEPTANCE.md，分别列local_v1和api_verified_v1状态、实际证据、已知限制、恢复方式和发布步骤。T24未请求则保持not_requested。

所有必需验收通过才能标对应交付等级完成；若仍有失败，报告未完成项及下一步，不写“完整项目已完成”。
```

## 推荐使用节奏

一个执行模型沿同一账本依次完成阶段。优先让它先交付S0和S1的可运行结果，再继续S2/S3；这是验收节点，不是要求每到节点就停工等确认。执行模型可以把较大任务拆成子编号，并持续更新状态。

如果更换模型或新建会话，把项目目录和“继续提示词”交给新执行者即可。账本的事实、失败命令、迁移状态和下一动作比口头“继续优化”更重要。
